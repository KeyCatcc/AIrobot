## 4. 终端 3 / A：动作与舞蹈 HTTP 服务

```bash
workspace="/home/cat/rai/robot-control-ws"
source /opt/ros/humble/setup.bash
source "$workspace/motor_drive/install/setup.bash"
source "$workspace/robot_control/install/setup.bash"
source "$workspace/h2_moveit_config/install/setup.bash"
source /home/cat/rai/.robot_action.env

cd /home/cat/rai/robot-action-runtime

python3 -u scripts/action_http_server.py \
  --host 127.0.0.1 \
  --port 8766 \
  --bridge-map /home/cat/xmov_new/robot_control/ymbot_smpl_control/config/moveit_to_motor_mapping.yaml \
  --dance-player /home/cat/xmov_new/robot_control/ymbot_smpl_control/scripts/csv_joint_state_player.py \
  --head-follow-control-url http://127.0.0.1:8768 \
  --execute
```

预期启动信息包含 `execute=True`、`head_follow_handoff=True`。`--execute` 是真机模式；移除后普通动作仅 dry-run，舞蹈请求会被拒绝。

同一服务提供 `/actions`、`/dances`、`/cancel`、`/execution`、`/catalog`，不需要为舞蹈额外开服务。手势和舞蹈执行前请求终端 6 释放发布权；播放进程退出后通知恢复。取消舞蹈时保持忙碌直到回零结束。

舞蹈播放器必须是支持 `DANCE_CANCEL_PROTOCOL_V1` 的已更新版本，否则启用舞蹈的动作服务会拒绝启动。

## 7. 终端 6：人脸跟随、主动欢迎、控制权交接

```bash
workspace="/home/cat/rai/robot-control-ws"
source /opt/ros/humble/setup.bash
source "$workspace/motor_drive/install/setup.bash"
source "$workspace/robot_control/install/setup.bash"

python3 scripts/face_follow_head_ros.py \
  --camera-index 0 \
  --duration-sec 0 \
  --detector yunet \
  --publish-neck \
  --publish-rate-hz 10 \
  --max-yaw-deg 20 \
  --dispatch-greeting-action \
  --dispatch-greeting-speech \
  --greeting-action "欢迎您" \
  --greeting-text "您好，欢迎来到展厅。"
```

确认现场条件后输入 `PUBLISH_NECK`。预期出现：

```text
Head-follow control: http://127.0.0.1:8768
Duplex status gate ready: http://127.0.0.1:8767/status
```

`--duration-sec 0` 持续运行；改为 `105` 则 105 秒后退出。

行为规则：

- duplex 为 idle 时允许跟随；稳定访客在冷却条件满足时触发欢迎。
- listening、speaking、conversing 或状态接口不可用时暂停跟随，禁止主动欢迎。
- 对话最后活动后约 30 秒无新活动，duplex 才返回 idle；这与问候冷却是不同计时。
- 手势/舞蹈开始前头部回正并销毁发布器，完成后重建；重建后仍需 duplex 为 idle 才恢复跟随。
- 主动欢迎和 RAI 普通动作共用让权机制，不能另起一个 `/joint_states` 发布器。

## 8. 舞蹈人工播放、调速与取消

bishangguan 原始文件位置：

```text
/home/cat/rai/robot-action-runtime/configs/dances/bishangguan.csv
```

当前 CSV 为关节名表头、1304 帧，按 30 FPS 播放。默认速度 0.5，约 87 秒，加 6 秒回零；无音频、不循环、no_waist=true、墙钟推进、100 Hz 采样。无需旧的电机 ID CSV 转换步骤。

在临时终端执行以下任意一项，不要逐行连续启动多个舞蹈：

```bash
source /home/cat/rai/.robot_action.env
cd /home/cat/rai/robot-action-runtime

# 按清单默认速度播放
python3 scripts/dance_http_client.py --dance bishangguan

# 或指定本次速度；范围 0.05–1.0，不修改默认值
python3 scripts/dance_http_client.py --dance bishangguan --speed 0.7
```

取消与查询：

```bash
source /home/cat/rai/.robot_action.env
cd /home/cat/rai/robot-action-runtime
python3 scripts/dance_http_client.py --cancel
python3 scripts/dance_http_client.py --status
```

accepted 只表示任务受理。running 表示执行中；publication_finished、returncode=0 表示正常发布结束；cancel_requested 表示取消已请求；cancelled_returned_home、returncode=0 表示取消后的回零指令发布结束。以上均不替代机械到位反馈。

客户端 Ctrl+C 不会取消舞蹈；停止 HTTP 服务也不保证停止播放子进程。正常提前结束使用 --cancel，紧急情况使用现场急停。

## 9. 交互时间和动作幅度调整

编辑机器人实际文件：

```bash
nano /home/cat/rai/robot-action-runtime/configs/interaction.yaml
```

参数含义及仓库当前值：

- stable_before_attention_sec: 1.5，稳定目标进入关注状态的等待时间。
- greeting_cooldown_sec: 10.0，同一目标冷却，当前为临时测试值。
- global_greeting_cooldown_sec: 60.0，全局问候冷却。
- post_conversation_greeting_suppress_sec: 60.0，对话后的问候抑制。
- face_loss_to_idle_sec: 3.0，丢失目标后的状态超时。

机器人端手动改过的值以实际文件为准。若需快速重复测试，可暂将三个冷却统一改成 10.0；仅改同目标一项，仍可能被另外两项的 60 秒限制。保存后重启终端 6。冷却结束不保证立即问候，还需要 idle、稳定目标及状态机条件满足。当前启动参数会开启主动问候，因此 YAML 的 greeting_enabled=false 不代表本命令下关闭。

头部死区、限速和丢失回正参数位于 `/home/cat/rai/robot-action-runtime/configs/head_follow.yaml`，修改后重启终端 6。

单动作幅度在 `/home/cat/rai/robot-action-runtime/configs/action_catalog.json` 中修改对应动作的 amplitude。例如 present_left 的 0.35 改为 0.5 会同比放大该动作各关节。保存后重启终端 A 和 B，保持两端目录版本一致。不要用电脑旧清单覆盖机器人已验收的动作。

舞蹈默认速度在 `/home/cat/rai/robot-action-runtime/configs/dances/dance_catalog.json` 中修改；enabled 和 rai_exposed 同为 true 才会提供给 RAI。修改后重启 A、B。

## 11. 常用健康检查和故障定位

临时终端检查动作目录及执行状态：

```bash
source /home/cat/rai/.robot_action.env
curl --noproxy '*' -sS --max-time 5 \
  -H "Authorization: Bearer $ROBOT_ACTION_TOKEN" \
  http://127.0.0.1:8766/catalog
echo
curl --noproxy '*' -sS --max-time 5 \
  -H "Authorization: Bearer $ROBOT_ACTION_TOKEN" \
  http://127.0.0.1:8766/execution
echo
curl --noproxy '*' -sS --max-time 5 \
  -H "Authorization: Bearer $ROBOT_ACTION_TOKEN" \
  http://127.0.0.1:8768/status
echo
```

检查 duplex：

```bash
source /home/cat/rai/.duplex_control.env
curl --noproxy '*' -sS --max-time 5 \
  -H "Authorization: Bearer $DUPLEX_CONTROL_TOKEN" \
  http://127.0.0.1:8767/status
echo
```

检查 ROS 前先 source 终端 1 的 ROS 环境，再执行：

```bash
ros2 node list
ros2 topic info /joint_states --verbose
ros2 param get /moveit_to_motor_bridge config_file
```

常见问题：

- ASR 正常但没有 GESTURE prefix：检查终端 5 的 RAI_WAVE_BRIDGE、RAI_GESTURE_SOURCE 及实际运行脚本。
- skipped_expired：检查 B 启动信息 max_age_ms=3000 及实际决策时长。
- blocked_head_follow / HTTP 503：检查终端 6 的 8768 接口及 release 确认。
- Other /joint_states publishers detected：检查重复人脸进程、旧播放器或其他发布节点，保留互斥保护。
- /cancel 返回 404：检查终端 A 是否更新并重启；无运行舞蹈时正常返回 no_running_dance。
- RAI enabled dances 为 []：检查 enabled、rai_exposed，更新 A 后重启 B。
- 舞蹈执行但口头拒绝：确认 Robot dialogue 加载日志，重启 5 创建新会话。
- 人脸恢复后不动：查看 neck publisher restored 日志和 duplex 是否 idle；未开 duplex 时跟随会暂停。

## 12. 完整展示测试

1. 从画面外进入，安静站立并左右缓慢移动：观察头部方向与平滑性。
2. 稳定停留：一次欢迎语和欢迎动作，不连续重复。
3. “你们公司主要做什么？”：简要介绍；追问“能具体说说吗？”应承接上下文。
4. “具体报价是多少？”：资料不足时不编造。
5. “请向我点头。”“请向你自己的左侧做个介绍手势。”：逐项等完成，核对方向与幅度。
6. “来段表演吧。”：随机选择已开放舞蹈，简短口头确认，按 0.5 播放。
7. 第一轮等待完整播放与回零，确认可继续对话；另开一轮测试“停止跳舞”，确认取消回零。
8. “今天参观到这里，拜拜，下次见。”：自然告别并挥手。
9. 保持安静，duplex 回到 idle 后，验证头部跟随恢复。

不要求动作完成等同语音结束；当前未实现动作时长与语速联动。音乐同步、聊天习惯性伴随动作和拆分头部/上肢话题属于后续开发。

## 13. 停止顺序

若舞蹈正在运行，先请求 --cancel，等回零结束并观察实际姿态，再按 Ctrl+C 依次停止：6 → 5 → 4/B → 3/A → 2 → 1。普通动作先等播放结束。不要依靠关闭电机进程代替急停。
